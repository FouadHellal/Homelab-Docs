# DECISIONS — Architecture Decision Records

Format: Context → Decision → Rejected alternatives → Consequences. Status is *Proposed* until the owner approves M0a. Vendor facts cite their source and version, accessed 2026-10-18. "Verify at Mx" marks a fact to re-check against the live device or package before it is relied on.

## ADR-001 Tech stack
**Decision.** Keep the brief's defaults: Python 3.12 + uv (lockfile committed), FastAPI, SQLAlchemy 2 + Alembic, SQLite WAL, Pydantic v2, asyncssh, httpx, APScheduler, Jinja2 + HTMX + Cytoscape.js (vendored, no Node), official MCP SDK, pytest + hypothesis, ruff, mypy, Typer for the CLI, structlog for logging. Task runner: **poethepoet** tasks in `pyproject.toml` as the single source (`uv run poe check` works on Windows and Linux). The Makefile is a thin wrapper for Linux/CI.
**Rejected.** Make as the primary runner (not on stock Windows); `just` (extra binary); Node/Vite for the UI (build step, supply chain); Go (single binary, but the MCP SDK and team skills favour Python).
**Consequences.** CI matrix ubuntu + windows on 3.12 (3.13 added as non-blocking).

## ADR-002 Target-side SSH enforcement: forced-command probe (option a)
**Context.** SSH exec has no argv on the wire. The client sends one string that sshd hands to the user's login shell (`$SHELL -c "<string>"`). Client-side argv discipline therefore can't be the only control. Docker-group membership is root-equivalent and excluded.
**Decision.** Option (a), implemented in two scripts generated by `atlas targets render` into `docs/targets/` for the owner to install:
1. `authorized_keys` for the dedicated user `atlas-ro` (no password, shell `/bin/bash`, home not writable by others):
   `restrict,from="<collector-ip>",command="/usr/local/libexec/atlas-probe-gate" ssh-ed25519 AAAA… atlas@collector`
   (`restrict` disables pty, agent, port and X11 forwarding, and user rc.)
2. `atlas-probe-gate` (root-owned 0755, runs as `atlas-ro`): exact-matches `$SSH_ORIGINAL_COMMAND` against a fixed list (`atlas-probe os|net|ports|storage|services|cron|users|packages|docker|pi|version`). No splitting, globbing or eval. On a match it execs `sudo -n /usr/local/libexec/atlas-probe <section>`. Anything else exits 64 and is logged to syslog.
3. `/etc/sudoers.d/atlas-ro`: one exact-argv line per section (`atlas-ro ALL=(root) NOPASSWD: /usr/local/libexec/atlas-probe os, … `). No wildcards. `Defaults:atlas-ro !requiretty, env_reset, secure_path=…`.
4. `atlas-probe` (root-owned 0755, bash, Debian/Ubuntu): runs only read-only commands with fixed arguments and takes no free-form parameters. The docker section uses `docker inspect --format` with an **allowlisted field template**: `.Config.Env` is reduced to names *on the target*, and `Cmd`/`Args`/`Labels`/`Healthcheck` are emitted for collector-side redaction. Output is framed with a per-run random boundary so data can't forge section headers. The `version` section reports the probe SemVer and its own SHA-256; `atlas doctor` compares that to the expected hash.

**Rejected.**
- (b) sudoers listing docker/ss/etc. commands directly: sudoers argument matching is glob-based and easy to get wrong (`docker inspect *` allows `--format` template injection and `docker inspect` of arbitrary objects). The command surface becomes N binaries × their flags, and the client string still reaches a shell.
- (c) docker-socket-proxy (e.g. tecnativa) on a private interface: it adds a network listener on every host, and `GET /containers/{id}/json` still returns Env values, so secrets would cross the wire. It only covers Docker, so linux-ssh would still need (a) or (b).
- docker group: root-equivalent.
- An agent daemon: excluded by non-goals.

**Consequences.** The probe is a reviewed artefact with a version. Changing collector requirements regenerates it, and the owner reinstalls. Without sudo, sections that need root (ports with process owners, docker, root crontabs) degrade to partial results.

## ADR-003 Client-side SSH runner
**Decision.** `SshRunner` accepts only `ProbeSection` enum members (no strings). The exec string comes from a constant table, so there is no interpolation. Options: asyncssh `client_keys=[per-target ed25519]`, `known_hosts=<pinned file>` (unknown or changed key ⇒ refuse), `agent_path=None`, `agent_forwarding=False`, `x11_forwarding=False`, `request_pty=False`, `preferred_auth="publickey"`, `password=None`, connect/command timeouts, max output bytes (default 8 MiB) and line-length caps. No `subprocess`, no `shell=True` anywhere. A ruff `banned-api` rule and a test grep for it. A `demo:` transport replays fixtures behind the same allowlist.
**Rejected.** Paramiko (sync, weaker typing); OpenSSH binary via subprocess (Windows path and quoting issues).
**Verified (M1, asyncssh 2.24.1).** Option names were checked against the installed `SSHClientConnectionOptions`. `config=None` loads no `~/.ssh/config`. `agent_path=None` resolves to no agent; the default `()` would fall back to `SSH_AUTH_SOCK`. `known_hosts=(pins, [], [])` trusts exactly the pinned keys with no hostname matching, no CAs and no TOFU. Host key algorithms are limited to ed25519/ECDSA-P256, client keys to ed25519. Tests drive an in-process asyncssh server, including a hostile `~/.ssh/config`, a conflicting `known_hosts` and a bogus `SSH_AUTH_SOCK`.

## ADR-004 Proxmox access
**Facts.** PVE 9.2 is current (released 2026-05-21, Roadmap). PVE 9 dropped `VM.Monitor` and added `VM.GuestAgent.{Audit,FileRead,FileWrite,FileSystemMgmt,Unrestricted}`. `VM.GuestAgent.Audit` was added to the `audit` privilege group with `VM.Audit` (pve-devel series 2025-07-17, access-control patch 1/9), and PVEAuditor is, as far as I can tell, built from the audit groups in `AccessControl.pm` (not confirmed by a primary doc; verify at M3 with `pveum role list`). Separated API tokens get the intersection of user and token ACLs (User Management wiki). Backup job API: `schedule` replaces `starttime`/`dow` (9.2 notes).
**Decision.** User `atlas@pve` (no password login needed), token `atlas@pve!collector` with **privsep=1**, role **PVEAuditor** on `/` for both the user and the token. If the guest-agent IPs come back empty, add a custom role `AtlasGuestAudit = VM.GuestAgent.Audit`. `atlas doctor` reads `GET /access/permissions` and **fails if any non-Audit privilege is present**. TLS: pin the PVE CA or leaf fingerprint. Endpoints (GET): `/version`, `/cluster/status`, `/cluster/resources`, `/cluster/backup`, `/cluster/backup-info/not-backed-up`, `/cluster/ha/resources`, `/cluster/sdn/vnets`, `/nodes`, `/nodes/{n}/status`, `/nodes/{n}/network`, `/nodes/{n}/storage`, `/nodes/{n}/qemu`, `/nodes/{n}/qemu/{id}/config`, `/nodes/{n}/qemu/{id}/agent/{network-get-interfaces,get-osinfo}`, `/nodes/{n}/lxc`, `/nodes/{n}/lxc/{id}/config`, `/nodes/{n}/lxc/{id}/interfaces`. Verify each path and privilege in the API viewer at M3.
**Rejected.** root@pam token (full write); a PVEVMUser-type role (VM.PowerMgmt); SSH + `pvesh` on the nodes (shell on a hypervisor).
**Sources.** https://pve.proxmox.com/wiki/User_Management · https://pve.proxmox.com/wiki/Roadmap · https://lists.proxmox.com/pipermail/pve-devel/2025-July/073214.html · https://lore.proxmox.com/pve-devel/20250717133711.84715-9-f.ebner@proxmox.com/

## ADR-005 UniFi access
**Facts.** The official local **Network Integration API** is served at `https://<console>/proxy/network/integration/v1/...`, needs Network ≥ 9.3, and authenticates with header `X-API-KEY`. The newest reference seen is v10.6.102. Lists are paginated with `offset`/`limit` (max 200) plus `filter`. Read coverage (v10.3.58 reference): info, sites, devices + details (ports, radios, `uplink.deviceId`) + latest stats, clients, networks, Wi-Fi broadcasts, firewall zones/policies/ordering, ACL rules, DNS policies, traffic matching lists, switch stacks/LAGs/MC-LAG, WANs, VPN, RADIUS profiles, device tags. The same API exposes POST/PUT/PATCH/DELETE and **actions** (device/port/client actions, vouchers). **API keys have no read-only scope; a key inherits the permissions of the admin who created it.** The Integration API reportedly does **not** expose uplink port numbers, client→switch port mapping or LLDP; those live only in the Classic API (`/proxy/network/api/s/{site}/stat/device`, `/stat/sta`), which uses session login `POST /api/auth/login` and `X-CSRF-Token`.
**Decision.**
1. Primary: the Integration API with a key created **while logged in as a dedicated local admin limited to Network "View Only"** (restricted to local access, no MFA prompt path). If UniFi OS won't let a view-only admin mint keys, SECURITY.md will say so explicitly. The control is then the GET-only wrapper plus the key living only in a Docker secret, and the risk is documented.
2. Wrapper: GET only on an endpoint-template allowlist. **No** POST is registered for the Integration API. All `/actions` paths are blocked by an explicit deny pattern on top of the allowlist.
3. Wi-Fi: PSK/passphrase fields are dropped by the response schema (never parsed). The Redactor also covers `x_passphrase`, `passphrase`, `psk`, `wpa*key`.
4. Classic enrichment is **opt-in** (`legacy_enrichment: true`). It uses a separate view-only local account. The only registered POSTs are `/api/auth/login` and `/api/auth/logout` (schema-checked bodies, the password supplied by SecretResolver at send time and never logged). Reads are GET `stat/device`, `stat/sta`, `rest/portconf`, `rest/networkconf`.
5. `atlas doctor` reads `GET /v1/info` and records the app version. It warns if the version is newer than the tested schema set.

**Rejected.** The cloud Site Manager / connector API (`api.ui.com`, cloud dependency); SSH to the UCG (shell on the gateway, vendor discourages it); SNMP (UCG coverage is thin and gives no clients or firewall data); `aiounifi` / `unifi-controller-api` libraries (they bring write paths, and wrapping our own client keeps the read-only guarantee in our code).
**Sources.** https://developer.ui.com/network/v10.6.102/updatefirewallzone (version index) · https://developer.ui.com/network/v9.3.43/getdevicedetails · https://github.com/gigabrit/unifi-network-api-reference (v10.3.58, community) · https://github.com/uchkunr/unifi-best-practices (v10.1.68, community: key inherits creator permissions, Classic login/CSRF). **Verify at M4** against the OpenAPI spec of the UCG's installed version. Community sources are secondary.

## ADR-006 UNAS (UniFi Drive)
**Facts.** No official public UNAS/Drive API was found. Community integrations read `https://<unas>/proxy/drive/api/...`. With an API key you get storage, pools, disks, SMART and system data. Shares and snapshots need a local account (tested on UniFi OS 5.1.19 / Drive 4.3.6; 401 regressions seen on 5.1.33). Ubiquiti advises against SSH unless support asks, and the UNAS Pro runs its own sshd.
**Decision.** Best effort, in this order: (1) UniFi Network device record if the UNAS appears there; (2) Drive GET API behind `nas.drive_api: true` (API key only, GET allowlist, schema-tolerant parsing, every field optional); (3) `manual/nas.yaml` fallback merged as a "manual" facet. No SSH.
**Rejected.** SSH probe (appliance, vendor guidance); SMB/NFS enumeration (wrong layer, needs credentials).
**Sources.** https://github.com/LayerTM/unifi-unas-ha · https://help.ui.com/hc/en-us/articles/204909374-Connecting-to-UniFi-with-Debug-Tools-SSH. Verify at M4.

## ADR-007 Docker data path
**Facts.** Docker Engine API is at 1.56 (Engine 29.8). Engines from 29.3 on support API ≥ 1.40 (docs.docker.com/reference/api/engine).
**Decision.** Use the docker **CLI inside the probe** (`docker ps -a -q --no-trunc`, `docker inspect --format '<allowlisted template>'`, `docker image ls --format json`, `docker network inspect`, `docker volume ls --format json`, `docker compose ls --all --format json`). Compose project/service come from the `com.docker.compose.*` labels. Compose files are never read.
**Rejected.** The remote Engine API over TCP/TLS (write-capable, and the socket is root); socket-proxy (ADR-002c).
**Sources.** https://docs.docker.com/reference/api/engine/

## ADR-008 Read-only HTTP client
**Decision.** `ReadOnlyHttpClient` wraps httpx and accepts only `Endpoint` objects from a registry (`method`, `path_template`, typed path vars with regexes, allowed query keys, optional body schema for registered POSTs). Rules:
- Methods: GET, plus registered POSTs only.
- No `X-HTTP-Method-Override` family headers.
- Base URL pinned per source; redirects disabled.
- Path vars are validated, then percent-encoded. The final URL is re-parsed and must canonically equal the template expansion (catches `..`, `%2e`, `%252e`, `;`, `//`, backslash, NUL, unicode dot variants).
- TLS verify always on, with CA/fingerprint pinning. Response size and time caps.
- Every call goes through AuditLog with the template, never the expanded query values.

hypothesis-based fuzz tests try bypasses.
**Rejected.** Method allowlisting alone (path tricks reach action endpoints); per-collector raw httpx (no single choke point).

## ADR-009 Redaction
**Decision.** Two layers:
- **At source**: the probe's docker template emits env names only. Schemas never parse PSK, password or token fields.
- **Collector side**: `Redactor` runs over every model before persistence or logging, and as the final structlog processor. It uses:
  - key-name rules (`*pass*`, `*secret*`, `*token*`, `*key*` except an allowlist like `ssh_host_key_fingerprint`, `psk`, `auth`, `credential`, `dsn`);
  - value rules (PEM blocks, JWTs, `ghp_/gho_/github_pat_`, `glpat-`, AWS `AKIA…`/secret pattern, Slack, Stripe-like `sk_live_`, bearer headers, URL userinfo `scheme://u:p@`, DB DSNs);
  - CLI flags (`--password=x`, `-p x` in known tools, `--token x`, `PASSWORD=x cmd`);
  - cron/healthcheck lines;
  - a Shannon-entropy fallback for long tokens in argv/labels.

Replacement is `«redacted:<rule>:<sha256[:8]>»`. The hash is HMAC-keyed with a local secret, so change detection still works without dictionary attacks. Redaction counts are recorded per run.
**Rejected.** Only key-name rules (misses cmdline secrets); a full gitleaks ruleset at runtime (heavy). The gitleaks patterns are reused as a test corpus instead.

## ADR-010 Audit log
**Decision.** Append-only JSONL (`data/audit/audit-YYYY-MM.jsonl`), opened `O_APPEND`, fsync per record. Each record has `prev_sha256`, forming a hash chain, and the chain head is mirrored in the DB. `atlas audit verify` checks it. Fields: ts, scan_id, target, transport, op template (`atlas-probe docker`, `GET /api2/json/nodes/{node}/qemu`), status, duration_ms, bytes, refusal reason. There is no update/delete code path. Monthly rotation. The owner can ship it via the host's syslog/promtail if they want.
**Rejected.** DB-only (same blast radius as the data); remote syslog required (external dependency).

## ADR-011 Identity, snapshots and diff
**Decision.** Natural keys per SPEC §5. The snapshot is canonical JSON (sorted keys, normalized IPs/MACs, sorted set-like lists keyed by identity) hashed with SHA-256 and deduplicated. Volatile fields are declared on the model (`json_schema_extra={"volatile": True}`) and stripped before hashing, so an unchanged host produces no new snapshot. Events are derived by typed rules over the field-level diff (DeepDiff-style, own implementation for determinism).
**Rejected.** Diffing raw outputs (noisy, would require persisting unredacted data); generic DeepDiff with no model awareness (order noise, no typed events).

## ADR-012 Storage
**Decision.** SQLite in WAL mode via SQLAlchemy 2 (sync engine in a worker thread; async isn't needed at this scale). Portable types only, Alembic from the first table. The DB is sensitive: the volume lives on the encrypted VM disk, file mode 0600, and backups go through `atlas backup` (online `.backup`) for DEPLOY.md.
**Rejected.** Postgres in v1 (an extra service); SQLCipher (painful wheels on Windows; host-level encryption is enough for this threat model).

## ADR-013 Web UI and auth
**Decision.** Server-rendered Jinja2 + HTMX + Cytoscape.js (vendored; SHA-256 of each vendored file checked in a test). Strict CSP with per-request nonce, no inline handlers. Headers: HSTS (via proxy), X-Content-Type-Options, frame-ancestors 'none', Referrer-Policy no-referrer, COOP/CORP.
- Auth: local users, argon2id (argon2-cffi defaults or stronger), server-side sessions in the DB, cookie `__Host-atlas` with HttpOnly, Secure, SameSite=Strict, rotated on login, idle and absolute timeouts, login rate-limit/lockout.
- CSRF: synchronizer token per session on every non-GET request.
- OIDC: later, via authlib.
- `--insecure-http` only for localhost dev.

**Rejected.** SPA + JWT in localStorage; basic auth at the proxy only (no CSRF and no per-user audit).

## ADR-014 MCP server
**Facts.** The official Python SDK `mcp` has a 2.x stable line (mid-2026). 1.x is in maintenance. Verify the exact version on PyPI at M6.
**Decision.** Pin `mcp>=2,<3`. Tools are read-only query functions over the read models, with no scan trigger. Transports: stdio, and Streamable HTTP bound to the private interface behind the proxy, with a bearer token from a Docker secret (constant-time compare; 401 is not logged with the token). Result sizes are capped. Optional sanitize mode (THREAT-MODEL T-MCP).
**Rejected.** A custom JSON-RPC server; exposing an SQL tool (unbounded queries).

## ADR-015 Process model and scheduler
**Decision.** One container and one process: FastAPI (uvicorn) + APScheduler AsyncIOScheduler + MCP HTTP mounted as a sub-app. Scan lock = a DB row lease plus an OS file lock (`portalocker`, which works on Windows). Pin APScheduler 3.11.x and re-check 4.x stability at M6.
**Rejected.** Celery/Redis (overkill); a separate worker container (more moving parts for ~100 targets).

## ADR-016 Unknown-device discovery is passive
**Decision.** Candidates come only from UniFi clients/devices, Proxmox, and ARP/NDP neighbour tables from already-probed hosts. No ICMP or port scans.
**Rejected.** Ping sweep / nmap: active, noisy toward IDS, outside the "read-only" spirit.

## ADR-017 Container image and supply chain
**Decision.** Multi-stage build: `ghcr.io/astral-sh/uv` builder → `python:3.12-slim-trixie` runtime, digest-pinned, non-root uid 10001, `read_only: true`, tmpfs `/tmp`, `cap_drop: [ALL]`, `no-new-privileges`, healthcheck. `uv.lock` with hashes. CI: ruff, mypy, pytest (ubuntu + windows), gitleaks, pip-audit, Trivy image scan, SBOM (syft), build + push to GHCR with provenance on `main` tags only. Dependabot for pip, actions and docker. Actions pinned by SHA.
**Rejected.** Distroless (harder debugging, little gain over slim with a non-root user and ro rootfs); Alpine (musl wheels for argon2/cryptography).

## ADR-018 Secrets handling
**Decision.** `SecretResolver` reads `/run/secrets/<name>` (prod) or `./secrets/<name>` (dev, git-ignored, never read by Claude). Values are wrapped in `SecretStr` and only unwrapped inside the transport call. SSH private keys are mounted read-only. Names must match `[a-z0-9][a-z0-9_.-]{0,63}`; symlinks, directories and files over 64 KiB are refused. The 0600 check applies to the dev `./secrets/` directory only, because Docker Compose bind-mounts file secrets 0444 and ignores `mode`, so `/run/secrets` relies on container isolation (non-root, single-purpose container). `.env.example` only. gitleaks runs in pre-commit (staged changes) and in CI (full history). Fake secrets must contain `ATLASFAKE`, the only allowlist.
**Rejected.** Env-var secrets (they leak via `/proc`, `docker inspect`, crash dumps); a Vault (an extra service for a homelab).
